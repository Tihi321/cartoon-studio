# Cartoon Studio MCP guide

Cartoon Studio makes a series of cutout-puppet cartoons for children aged 4 to 8: the cast, the rigs and the sets are made once and reused, each episode has a Croatian and an English voice track over the same animation, and the base animation is rendered locally to MP4. This server lets an agent such as Claude Code drive the studio: see the series and the job queue, and do the model work of the jobs itself, at no cost.

**Status: pilot 2 (CTS-17).** Every tool below exists; the full list is at the end of this guide. Everything that needs ComfyUI, Flow, VibeTTS or a browser was checked with fakes only until the pilot runs it (what is UNTESTED is said under each section).

## Connect

- Port **7465** on 127.0.0.1 (`config/mcp.md`; `CTS_MCP_PORT` overrides it for one run, `yarn mcp --port N` too).
- Token: none by default. With a `token` in `config/mcp.md` (or `CTS_MCP_TOKEN`) every request must send `Authorization: Bearer <token>`.
- Only requests with a loopback `Host` and no foreign `Origin` are served.
- Claude Code: `claude mcp add --transport http cartoon-studio http://127.0.0.1:7465/mcp`
- Headless (no window): `yarn mcp` (= `node out/engine/index.js --mcp-only`). The app runs the same server while it is open.
- Stdio, for clients that cannot speak HTTP: `claude mcp add cartoon-studio -- yarn --cwd <repo> engine -- mcp`. It relays to the running engine when there is one, else it starts its own.
- Only one engine can use a data folder (`state/engine.lock` in it names the running one). A second start prints where the running one serves MCP.
- The data folder is `~/CartoonStudio` (`--data <dir>` or `CTS_DATA` change it). A series lives in `series/<slug>/`.
- The same port also serves two read-only pages: `/preview/` (the player bundle) and `/files/<series>/...` (files under `series/<series>/` only).

## Tools

All tool names start with `cts_`. Every call returns JSON, also as `structuredContent`; a failure is an error result with a message.

| Group | Tools |
|---|---|
| Queue | `cts_status {series?}` (the job counts of a series, or of every series; `clientTasks`), `cts_wait {series?, timeoutSeconds?}` (waits until the series has nothing left to run), `cts_pause_all`, `cts_resume_all`, `cts_stop_now {drop?, slug?}` |
| Client provider | `cts_client_tasks`, `cts_get_task {client?, role?, series?, task?}`, `cts_submit_task {taskId, text}`, `cts_release_task {taskId}` |
| Generators | `cts_studios_status` (ComfyUI, flow-music-mcp, VibeTTS) |

A job id is `<series>--<task>--<unit>--r<run>`, so `cts_status {series}` finds the jobs of a series by their prefix.

## Do the model work yourself

A role or agent set to the model `client/claude-code` (in `config/roles.md`) parks its model calls in the engine's client task queue. `cts_wait` returns with `clientTasks`; then loop: `cts_get_task` (takes the oldest waiting call, leased for 30 minutes) -> write the answer -> `cts_submit_task {taskId, text}`. When the task has a schema the answer is checked: a failed check returns `{accepted: false, problems}` and the task stays yours, so fix the text and submit again. `cts_client_tasks` lists the waiting and leased tasks; `cts_release_task` gives one back. A task is for one client model: without `client` you get the `claude-code` ones. The queue is lost when the engine restarts: the running job is asked again.

## Budget and images (CTS-08)

| Tool | What it does |
|---|---|
| `cts_budget_set {series, episode, capUsd, flowCreditsCap?, approvedBy, note?}` | Writes `episodes/<ep>/budget.json` (with `approvedAt`). Call it only after the user approved the amount. Without it both caps are 0 and every paid call is refused. |
| `cts_budget_get {series, episode}` | Caps, spent per currency (usd, credits), what is left, and the ledger `spend.json`. |
| `cts_media_config {series?, episode?}` | Read-only: the image model (`comfy.imageModel`) and the fallback order (Z-Image at a lower denoise, Qwen edit, then Nano Banana only after the user's yes), the music engine (`comfy.musicModel`, the alternatives, the sound-effect engine) and the USD cap that gates Nano Banana. The Settings view shows it. |
| `cts_image_generate {series, episode, provider?, prompt, width?, height?, format?, out?, refs?, model?, seed?}` | `comfy` (default, also `auto`): local, free; `refs` makes it an edit (Qwen). `gemini` (Nano Banana): paid, refused with `BUDGET_EXCEEDED` at cap $0 before any network call; needs the user's yes and a recorded cap. `fal`: paid, charged to the episode budget. No image goes through Flow. |

Every paid call goes through `charge` (`src/engine/budget/spend.ts`): the price estimate (from `config/prices.md`, unverified, check before use) is checked against the cap BEFORE the call (`BUDGET_EXCEEDED` for dollars, `FLOW_CREDITS_EXCEEDED` for Flow credits) and the real cost is appended to `spend.json` afterwards. A series-level spend (the series intro or outro clip) is charged to the episode that triggers it. The key for `fal` is read only from this tool's credential store: a missing one is `KEY_MISSING <provider>`; store it with `node out/engine/index.js key-set fal`.

## Voices and music (CTS-06)

| Tool | What it does |
|---|---|
| `cts_voice_plan {series, episode, lang?, provider?}` | Speaks nothing. The clips (script lines x series languages) with their state (`current`, `new`, `changed`, `redo`, `forced`), `allocation` per language (`{lang, need, provider, chain, reason, credits?}`: whole languages, Croatian first; ElevenLabs when every speaker has an ElevenLabs voice id and the estimate fits in its free credits minus the reserve, else Gemini within its free quota, else the local chain), `credits` (the ElevenLabs estimate per language: characters x the model's multiplier), `elevenlabs` (`{ready, tier, remaining, reserve, left, resetAt, reason?}`, null when not used), what is left of the Gemini quota (`quota`), what is up (`availability`), and warnings (bad OmniVoice tags, missing texts or voices, `W_VOICE_ID_CHANGED` when a character's ElevenLabs voice id differs from the one its first episode used). |
| `cts_voice_generate {series, episode, lang?, ids?, force?, provider?}` | Returns a job id; the job speaks every clip that needs it and writes `episodes/<ep>/voice/<lang>/<line>.wav` (44.1 kHz mono, edge silence trimmed) and `manifest.json`. A clip is made again only when its hash (text, language, voice, speed, style) changes; a clip no provider can speak becomes a silent placeholder (2.5 words a second) with status `placeholder` and a warning, never a failed run. `costUsd` is 0. |
| `cts_voice_status {series, episode}` | Per language: the allocation, every line's status/provider/engine/seconds, total seconds; and the voice jobs of the series. |
| `cts_voice_quota {reset?}` | `{ gemini, elevenlabs }`. `gemini`: today's Gemini TTS counter (`state/gemini-tts.json`): `limit` 10, `used`, `remaining`, `day`, `tz`; the day ends at Pacific midnight; `reset: true` sets today's count back to 0. `elevenlabs`: the free tier read live through flow-music-mcp (`flow_elevenlabs_status`): `{ ready, tier, remaining, reserve, resetAt, reason? }` (`reason` when not ready: no key, flow-music-mcp down, a refusal code). The Settings view shows both. |
| `cts_voice_audition {series, cast, lang, provider: "elevenlabs", voiceIds, model?, text?, language?, episode?}` | Speaks one line (`text`, else the character's first catchphrase in `lang`) with each ElevenLabs `voiceId` (premade voices from flow-music-mcp `flow_elevenlabs_voices`; at most 8) and writes `cast/<id>/voice/audition-<lang>-<voiceId>.wav` (with `-<model>` added when `model` is not `eleven_multilingual_v2`, so a model can be heard side by side; `language` is the code sent to ElevenLabs, e.g. `hr` for `eleven_flash_v2_5`). The whole estimate is checked against the remaining credits minus the reserve before anything is sent (`E_ELEVEN_QUOTA`, nothing sent). **Pass `episode`** so the credits go into that episode's `spend.json` (currency `eleven-credits`, USD 0). Returns `{cast, lang, model, text, clips: [{voiceId, file, seconds, credits}], credits, remainingAfter, ledger, error?}`. The user picks by ear; the chosen id goes into the bible as `voice.<lang>.elevenlabs = {voiceId, name, model?, settings?}` with `cts_series_update`. |
| `cts_music_generate {series, tags, bpm?, seed?, seconds?}` | Returns a job id; ComfyUI (`config/providers.md` `comfy.musicModel`: `ace-step-v1-instrumental` by default, `minimax-music-3` as the alternative) makes `series/<slug>/music/theme.ogg`, a 40 s instrumental with a 0.5 s fade-in and a 2 s fade-out; the job result is `{file, seconds, engine, wallSeconds}`. Sound effects (up to 2, `moss-soundeffect-v2`) are made by the pipeline's `music` step. ComfyUI down or failing = a warning in the job log and no music. Free and local. |

Who speaks: the hub rule (`config/voice.md`). **ElevenLabs first** (HUB-31): its free tier through flow-music-mcp (`flow_narrate` engine `elevenlabs` with word timestamps); the key is set by the user only, in `ELEVENLABS_API_KEY` or `~/.flow-music-mcp/.env` (no tool sets it, Cartoon Studio never holds it); a language goes to ElevenLabs when every speaker has `voice.<lang>.elevenlabs.voiceId` and the estimate fits in `remaining - reserve` (`config/voice.md` `elevenlabs: {model, reserve}`); flow-music-mcp refuses past the free quota and any paid tier, so it never costs money; its lines carry `wordsFrom: "elevenlabs"` (no whisper). Then Gemini (`flow_narrate`, engine `gemini`, one request per clip) only when a whole language fits in the free requests left today; otherwise the local chain `localOrder`: Croatian OmniVoice through ComfyUI, then Supertonic through VibeTTS; English Kokoro through VibeTTS, then OmniVoice. A character's bible voice can pin `comfy`, `vibetts` or `paid` (the paid slot goes through the budget gate and then throws `NOT_IMPLEMENTED` in phase 1). OmniVoice reads `voice.<lang>.comfy.instruct` as attribute tags only (`male|female`, `child|teenager|young adult|middle-aged|elderly`, `very low|low|moderate|high|very high pitch`, `whisper`, and one English accent); other words are dropped with a warning in `cts_voice_plan`. ComfyUI memory is freed (`comfyKindSwitch`, `src/engine/comfy/kind-switch.ts`) before voice work after image work and the other way round.

## Render and sheets (CTS-05)

| Tool | What it does |
|---|---|
| `cts_render {series, episode, langs?, quality?, maxSeconds?, wait?}` | Returns one job id per language (`<series>--render--<ep>-<lang>-<quality>--r<n>`); the Canvas player in headless Chromium draws every frame, ffmpeg encodes (`h264_amf` when it works on this machine, else `libx264`), the audio is mixed (each input is brought to its level from `config/render.md` `mix`: voices -20 LUFS, music 18 dB under the voice while someone speaks and 8 dB under in the gaps, then -16 LUFS on the sum; a final render also writes `render/<lang>/mix-check.json` and `cts_render` returns `minUnderDb`). `quality: final` -> `episodes/<ep>/out/<lang>.mp4` (1920x1080, real clips spliced in); `preview` -> `out/<lang>.preview.mp4` (960x540, clips show a placeholder card). `render/<lang>/render.log` has the frames, stage times and encoder. A missing clip file that is not marked `fallback` fails the final render (`E_CLIP_MISSING`); a `fallback` clip shows the cutout scene with the actors bouncing.    **A Blender series** (bible `renderer: "blender"`): the same tool renders with headless Blender (EEVEE) instead. The assembled scene `render/<lang>/scene.blend` is used (assembled again when the timeline changed); Blender renders PNG frames in chunks of `chunkFrames` (`config/blender.md`, default 240), the engine encodes each finished chunk (`h264_amf`, else `libx264`) while the next renders and deletes its frames, the chunks and the real Flow clips are joined with the concat demuxer, and the mix, splice and mix check are the canvas render's. Preview is `preview.width x height` with `preview.samples` (960x540, 4), final `final.*` (1920x1080, 16). A preview shows the actors during a clip range (no placeholder card). The result has `blenderTimes` (`first`, `warmMean`, `p95`, `total`, seconds per frame); `render/<lang>/blender-times.json` (and `blender-times.<quality>.json`) has every frame and `render.log` the same numbers beside the stage times. |
| `cts_render_status {id?}` | State (running, done, failed), progress in frames, and the result or error of the render jobs of this engine session (they are not in the markdown job queue: a render needs no model). |
| `cts_frames {series, episode, lang?, count? or times?}` | Contact sheet PNG of N frames (default 12) with time labels: `episodes/<ep>/render/<lang>/sheet-<n>.png`. Returns the path and the picture. A Blender series: the frames are cut from the rendered `out/<lang>.preview.mp4` (the final when there is no preview), so render first; Blender tiles and labels them. |
| `cts_pose_sheet {series, cast, variant?}` | Pose sheet PNG of a rig: `cast/<id>/rig-sheet.png` (or the variant's; `sheet.png` is the character sheet). Returns the path and the picture. |

The render serves the player and the series folders itself on a random 127.0.0.1 port (same routes as the MCP server's `/preview/` and `/files/`), so it does not need the MCP server or its token. `state/encoder.json` caches the encoder probe (delete it to probe again). Sizes, fps, encoder order, frame format and loudness are in `config/render.md`.

## Blender (CTS-18, CTS-20, CTS-21)

| Tool | What it does |
|---|---|
| `cts_blender_status {}` | Is Blender usable: the path of `config/blender.md` exists (`E_BLENDER_MISSING` if not), its version is the pinned major.minor (`E_BLENDER_VERSION` if not, unless `allowUntestedVersion`), and the GPU EEVEE would use (a headless `probe` run, `gpu.platform`). Returns `{ ok: true, path, version, gpu }` or `{ ok: false, code, message, path }`. The version is read once per engine start. |
| `cts_blender_config {path?, version?, allowUntestedVersion?, chunkFrames?, preview?, final?}` | Reads `config/blender.md`; with fields it changes them (`preview` and `final` take `{width?, height?, samples?}`). Blender is checked again at the next use. |
| `cts_character_set {series, cast, spec}` | Checks and writes the 3D spec `cast/<cast>/character.json` (`cts.character3d/1`, see `seed/style/toon-3d.md`); sets the cast member's `character` path in the bible. Returns `{ file, specHash }`. |
| `cts_character_build {series, cast, sheet?}` | Builds the character with Blender: `character.blend`, `sheet.png` (turnaround, six mouths, blink, half lid, happy, sad, surprised, looks; pieces in `sheet/`) and `build.json` (spec hash, controls, determinism hashes, warnings). A queue job (`<series>--character_build--<cast>--r<n>`, `job.progress`); its result is JSON `{ ok: true, blend, sheet, warnings, buildSeconds }` or `{ ok: false, code, message }` for a spec Blender cannot build (`E_FACE_HIDDEN`, `E_SPEC_INVALID`). |
| `cts_character_get {series, cast}` | The spec, `specHash`, the last `build.json`, `stale` (the spec changed since the build) and the `sheet.png` picture. |
| `cts_set3d_set {series, set, spec}` | Checks and writes the 3D set spec `sets/<set>/set3d.json` (`cts.set3d/1`: ground and patches, sky, props from the kit, marks, named cameras). Returns `{ file, specHash }`. |
| `cts_set3d_build {series, set, sheet?}` | Builds the set with Blender: `set.blend`, `sheet.png` (auto wide, two stand-ins on the first two marks, the first two named cameras) and `build.json`. A queue job (`<series>--set_build--<set>--r<n>`); the result is `{ ok: true, blend, sheet, warnings, buildSeconds }` or `{ ok: false, code: "E_SET_INVALID", message }`. Warnings: a mark inside a prop footprint (`blender/cts_blender/props.json`), a bench without a seat. |
| `cts_scene_assemble {series, episode, lang?}` | Assembles the 3D scene of a Blender episode from its timeline and the built assets (one job per language, all when `lang` is left out; role `background-artist`, no model): appends the set and characters, puts the actors on their marks, runs the acting library on the timeline's actions, keys mouths, lids and pupils, frames `wide`, `two`, `cu-<id>`, `ots-<a>-<b>` or a named camera of the set, adds the title cards as 3D text over a plate, and writes `episodes/<ep>/render/<lang>/scene.blend` and `assembly.json`. The result is `{ ok: true, blend, assembly, frames, actions, shots, warnings }` or `{ ok: false, code, message }` (`E_ACTION_UNKNOWN`, `E_MARK_UNKNOWN`, `E_SHOT_UNKNOWN`, `E_ASSEMBLE_FAILED`). |
| `cts_still {series, episode, lang?, t, width?, height?, samples?}` | One frame of the assembled scene as a PNG (default 960x540, 4 samples) at `t` seconds, written to `render/<lang>/still-<frame>.png` and returned as a picture. Runs Blender and waits. For a quick look, and the keyframe of a Flow clip. |
| `cts_set3d_get {series, set}` | The spec, `specHash`, the last `build.json`, `stale` and the `sheet.png` picture. |

Every Blender run is `blender -b --factory-startup --python-exit-code 1 --python blender/run.py -- <job.json>` with `PYTHONNOUSERSITE=1`. The job is `{command, ...}`; `blender/run.py` prints `CTS {...}` lines (`progress`, `chunk`, `result`, `error`) that the runner (`src/engine/blender/runner.ts`) turns into progress events and the result. A non-zero exit without a result is `E_BLENDER_FAILED` with the last 40 log lines.

## Series, rigs, sets, episodes and the pipeline (CTS-07)

The model work of the pipeline is done through the client task tools above; `docs/pipeline.md` has the steps, the pause, the role task contract and the files.

| Tool | What it does |
|---|---|
| `cts_run_pipeline {series, episode, brief?, options?, retry?, from?}` | Starts or resumes the episode pipeline (creates the series from the brief when it does not exist). `options.renderer: "blender"` (a new episode of a new series, or a series whose bible says `blender`) runs the 3D list: bible (with `style3d.json`), characters (designer spec, Blender build, self-review of `sheet.png`, at most 2 revisions), the pause for the user's approval of every sheet, sets, script (the writer gets the acting library names, marks and shots), safety, voices (with whisper words), music, Flow clips (keyframe = a Blender still), 3D timelines with lint, assemble, Blender preview, frame review, final renders; `docs/pipeline.md` has the table. `options.skipAuditions: true` leaves out the audition lines of the voice casting. The first call needs `brief {idea, title?, ageMin?, ageMax?, notes?, seconds?, lineRange?, intro?, outro?}`. Answers with the state, the current step, every step, a `hint` on what to do next, the pitches while they wait and the `summary` when done. Re-calling with the same ids resumes; it never skips a pause. `brief.pitch` (a pitch object) is the user's earlier pick: the pitch step and its pause are skipped. `retry: true` puts failed steps back; `from: "<step>"` redoes a step and everything after it; `options {rigPaths (default raster), rigChoice, poses {castId: [gesture]}, poseFacePlates, skipClips, clipCredits}`. Step order: pitch (or `brief.pitch`) -> bible -> cast_sheet -> sheet_review (pause) -> rig -> poses (optional) -> set -> script -> safety -> voice_cast -> voice -> music -> clip_shots -> clips -> timeline -> preview_render -> frame_review -> final_render (with the mix check). |
| `cts_pitch_choose {series, pitch}` | The user's pick of premise p1/p2/p3: writes `bible.chosenPitch` and `chosenAt`, and lets every pipeline that waits go on. Call it only with the pitch the user chose. |
| `cts_voice_approve {series, ok, note?}` | CTS-37: the user's verdict on the voice cast of a `blender` series. The pipeline waits at `voice_review` after `voice_cast` and before any line is spoken; play the auditions (`cast/<id>/voice/audition-<lang>-<voiceId>.wav` when the cast has ElevenLabs voices and the free tier is ready, else `cast/<id>/voice/<lang>.wav`); other voices can be tried with `cts_voice_audition` and set with `cts_series_update` first. `ok: true` writes `voice-review.json {ok, at, voicesHash}` and resumes the waiting pipelines (a voice changed later needs a new approval); `ok: false` needs a note, which goes to the voice director in a new casting round, and the run waits here again. Returns `{ok, at, voicesHash, voices, resumed, warning?}`. Call it only with the user's answer. |
| `cts_sheet_approve {series, cast, ok, note?}` | The user's verdict on one character sheet. A `blender` series: `cast/<id>/sheet.png` is the turnaround, expressions and mouths Blender rendered from the spec; `ok: true` writes `bible.cast[].sheet {approvedAt, specHash}` and is refused when the spec changed after the last build; `ok: false` needs a note and the designer builds that character again with it (a changed spec makes an old approval void). A canvas series: `cast/<id>/sheet.png` is master + wave, point, shrug. The pipeline waits at `sheet_review` until every character is approved; `ok: true` writes `bible.cast[].sheet`; `ok: false` needs a note and makes that sheet again with new seeds. Call it only with the user's answer. |
| `cts_series_create {slug, title?, logline?, ageMin?, ageMax?, languages?}` | A stub bible. Usually not needed. |
| `cts_series_get {series}` | The bible, pitches and the chosen one, the rig variants per character (with `hasRef` and the sheet approval `sheet {approved, approvedAt, review, poses}`), the episodes and the pipelines. |
| `cts_series_update {series, title?, logline?, tone?, rules?, audience?, languages?, style?, music?, cast?, sets?}` | Changes the bible (validated). The pitches and the choice cannot be changed here. |
| `cts_cast_get {series, cast?}` | The cast entry (a `blender` series also gets `character {specHash, body {kind, vehicleType?}, build, stale, approvedSpecHash, approvalHolds}` and `files.concept`), the rig (parts, gestures, emotions), the variants (path, wall time, spend), `cts_rig_check` of the chosen rig and of each built variant, the sketch, master (`ref.png`), character sheet and rig sheet paths, and the sheet approval (`sheet {approved, approvedAt, review, poses}`). |
| `cts_rig_check {series, cast, variant?}` | (CTS-02) The part rules, all 8 mouths, 3 eye states and 4 brows. |
| `cts_set_get {series, set?}` / `cts_set_update {series, set, groundY?, actorScale?, layers?, marks?, shots?}` | Read a set (or list them); change it (marks and shots merge by name, `null` removes one). Validated. |
| `cts_episode_create {series, episode, title?, cast, set, shot?, mark?}` | A hand-made episode: a one-scene stub script, registered in the bible. |
| `cts_episode_get {series, episode?}` | Script, both texts, voice status per line, timelines, reviews, clips, budget and spend, pipeline. Without an episode: the list. |
| `cts_script_set {series, episode, script}` / `cts_text_set {series, episode, lang, text? or strings?/lines?}` | Write the script / one language's text (validated; `strings` and `lines` merge into the catalog). |
| `cts_timeline_build {series, episode}` | Lip-sync and the timelines of all languages (needs the voices). For a `blender` series: six-viseme lip-sync (`words-<lang>` from the manifest's whisper words, else `text-<lang>`) and `cts.timeline3d/1` timelines (same actions in the same order in every language, times from the voices). Then `cts_lint {requireAudio: true}`. |
| `cts_clip_plan {series, episode}` | The missing Flow clips, their shots, the credit cap and spend, and the `video-plan.mjs` commands (`plan`, `next`, `record`) for the hub session. |
| `cts_clip_generate {series, episode?, clip: "intro"\|"outro", maxCredits}` | Job: keyframe (a still of the clip's `staging`, 1280x720, `clips/keyframes/<id>.png`: our own player draws it for a canvas series, Blender renders it from the built characters and set for a `blender` series, the same `still` command as `cts_still`; it is the only picture that goes to Flow), the 8 s video scene (`max_credits` = `maxCredits`, charged to the Flow credit cap), review (one retry, then `fallback`). Refuses without a recorded `flowCreditsCap` and past it; any other clip id is refused (no hero clip). `episode` only names the budget that pays. |
| `cts_clip_review {series, episode?, clip}` | Job: the frame-critic reviews six frames of the clip next to the pose sheets. |

`cts_status {series}` also lists the pipelines of the series (a `blender` series adds `blender {task, unit, stage, fraction}` while a character or set build, the assembly or a render runs): `state` (`running`, `waiting-on-user` after the pitches until `cts_pitch_choose`, or while Flow clips wait for a credit cap; `waiting-on-client`; `failed`; `done`), the current step and a hint.

UNTESTED against the real services (checked with fakes): ComfyUI image jobs (`cast_sheet` in the app's flow, `set`; the sheet images were probed live with a hand-made body plan, not through a model task), Flow video (`flow.generateVideo` is new in `studios/flow.ts` and follows `flow_generate` in `flow-music-mcp/src/flow/tools.ts`), the player still of a clip (Chromium), the VibeTTS calls of the pipeline, and the pose sheets and renders (Chromium).

## Retired in CTS-28

The cutout authoring path was retired when the Blender backend landed (HUB-30). These tools no longer exist: `cts_rig_set`, `cts_rig_build`, `cts_rig_compare`, `cts_rig_choose` (rigs were built from Z-Image sheets or drawn as SVG), `cts_pose_make` (pose images) and the background-removal helper behind the 2D set step (`cts_cutout`). In a `canvas` series the steps `cast_sheet`, `rig`, `poses` and `set` answer `E_RETIRED` ("cutout authoring was retired in CTS-28"); a finished canvas pilot keeps them done. What stays for canvas series: `cts_rig_check`, `cts_pose_sheet`, `cts_lint`, `cts_set_get` / `cts_set_update`, `cts_timeline_build`, `cts_render`, and `cts_image_generate` (ComfyUI Z-Image text-to-image, image-to-image and inpaint; Gemini and fal behind the budget gate) for concept art and clip polish.
